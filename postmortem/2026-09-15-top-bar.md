# Top bar disappears again on an empty workspace

## Report and investigation

The top bar stays hidden after a workspace switch finishes while live wallpaper
is running. The installed extension already contained the earlier fix that clears
fullscreen state, and Shell started after that installation. The delay fix from
the preceding task was still only in the source checkout.
The CLI installer was also found to skip copying the bundle if the extension
directory already existed. It now stages and replaces existing installations;
a regression test verifies repeated updates in a private data directory without
a session bus. This installation issue does not explain the recurrence by itself,
since the installed code already included the earlier fullscreen-state fix.

The existing isolated Shell suite passed on both one and two virtual monitors.
A separate single-monitor probe also passed repeated switches between a regular
fullscreen application and newly created dynamic workspaces, including overview
transitions and deliberate fullscreen state on owned wallpaper windows. In that
probe the wallpaper remained a desktop window, its fullscreen flag was false,
and the top bar remained visible. These results do not reproduce the reported
physical-display failure.

## Additional rendering path and guard

Mutter 50.4's [Wayland scanout candidate selection](https://github.com/GNOME/mutter/blob/50.4/src/compositor/meta-window-actor-wayland.c)
accepts an opaque surface matching the window's painted bounds even without a
fullscreen flag. Its [native compositor view](https://github.com/GNOME/mutter/blob/50.4/src/compositor/meta-compositor-view-native.c)
then checks the monitor bounds and the hardware display controller. Virtual
monitors cannot exercise this hardware path. Direct scanout is therefore a
plausible explanation for the gap between the user's report and the passing
headless tests; it is not yet confirmed by a trace of the failing display.

The extension now holds a [compositor unredirect inhibitor](https://mutter.gnome.org/meta/method.Compositor.disable_unredirect.html)
while wallpaper is visible, including manual pause. This keeps the wallpaper in
the normal Shell composition path. Coverage events update the hold immediately,
and covering all displays, stopping, renderer failure or disabling releases it.
The inhibitor is reference-counted; the extension acquires at most one reference
and never releases a reference belonging to another component.

The API is compositor-wide. If wallpaper remains visible on a secondary display,
direct scanout is also inhibited for applications on the primary display. Fully
covered desktops release the hold, allowing fullscreen applications to regain the
optimization. Ordinary fullscreen applications retain GNOME's panel behavior.

## Verification

Run `bun run check`, `bun test`, `bun run test:shell`,
`WALLSHADER_TEST_MONITORS=1 bun run test:shell`, and the native smoke test on a
private virtual display. Shell tests cover immediate workspace playback updates,
panel visibility, manual pause, fullscreen applications, and inhibitor cleanup.
The logic test exercises repeated visibility changes and independent inhibitor
owners.

After installation, log out and back in to load the new Shell module. Check empty
workspaces after fullscreen apps, manual pause/resume and Activities on the
physical display. The guard's lifecycle can be verified in virtual tests, but
resolution of the reported hardware symptom still requires that physical check.
